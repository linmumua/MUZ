# 斗地主模组自动迭代策略

## 迭代原则
1. **渐进式改进**：每次迭代专注于一个具体的改进点
2. **版本管理**：每次迭代增加小版本号（如1.6.18 → 1.6.19）
3. **质量保证**：确保代码质量和向后兼容性
4. **详细记录**：每个版本都有完整的更新日志

## 版本号规则
- 主版本号（Major）：重大架构变更或功能重构
- 次版本号（Minor）：新功能添加
- 修订号（Patch）：bug修复和小改进

当前版本：1.6.17
迭代将从1.6.18开始

## 迭代目录结构
```
iterations/
├── v1.6.18/
│   ├── CHANGELOG.md      # 本次更新详细记录
│   ├── src/              # 复制的源代码
│   ├── build.gradle.kts  # 复制的构建配置
│   └── README.md         # 版本说明
├── v1.6.19/
│   └── ...
└── ITERATION_STRATEGY.md # 本文件
```

## 可能的改进方向
1. **代码质量**
   - 代码重构和优化
   - 添加单元测试
   - 改进错误处理

2. **功能增强**
   - 新的游戏模式
   - 用户界面改进
   - 性能优化

3. **兼容性**
   - 支持更多Minecraft版本
   - 与其他插件更好的集成

4. **用户体验**
   - 更好的配置选项
   - 改进的文档
   - 更多的自定义选项

## 迭代流程
1. 分析当前项目状态
2. 确定改进点
3. 实现改进
4. 测试验证
5. 更新版本号
6. 创建版本归档
7. 记录更新日志

## 监控机制
- Overseer将监控迭代进度
- 确保每次迭代都有明确的目标和成果
- 定期检查代码质量和功能完整性
