# MUZ 已移除功能与配置键

> 本文记录**被刻意删掉的东西**：为什么删、删了之后什么代码还在为它兜底、以及哪些不要「顺手加回来」。
> 依据仓库实际代码事实撰写，每条都注明取证位置。
>
> 存在意义：这些决策的理由散落在各处代码注释里，改动相邻代码时很容易看不见，
> 于是把删掉的功能又「修回来」。本文是那些注释的索引。

## 一、渲染实体

### 1. 座位旁悬浮头像（seat-avatar）

**删的是**：每个座位旁一个 `ItemDisplay` 玩家头颅。现在座位只显示名字。

**连带删掉的配置键**（`RETIRED_RENDER_KEYS`，`DoudizhuPlugin.java:3189`）：

```
render.seat-avatar.scale
render.seat-avatar
render.seat-avatar-offset.lateral / .vertical / .depth
render.seat-avatar-offset
render.player-head-show-id     头像/名字显示模式枚举，座位现在恒显示名字
render.player-head-scale       原是 seat-avatar.scale 的迁移默认值，两者都删了
```

### 2. 桌心悬浮头像（status-avatar）

**删的是**：桌子正中上方那个悬浮头颅 `ItemDisplay`。

**连带删掉的键**：`render.status-avatar`、`render.status-avatar-offset`。

**兜底代码不要动**（`PhysicalTableManager.java:131` 与 `:3713`）：

```java
private static final double RETIRED_STATUS_AVATAR_VERTICAL_OFFSET = 0.82;
```

生成代码已经没了，但**升级前已经生成的实体还留在世界里**，而持久化不存实体 id，
只能靠 `purgeResidualWorldArtifacts` 按坐标扫回收。它悬在 anchor 上方约 3.9 格
（旧默认 `status-height` 3.10 + 偏移 0.82），其余热点都在低处、垂直半径 1.6 够不到，
所以**必须单独补这一条热点**。

这个常量不是「还能调的参数」，是考古坐标。

### 3. 屏幕中央的「轮到谁出牌」头像 Title

**删的是**：屏幕正中偏下弹出的那条头像 Title。

**连带删掉的键**（`DoudizhuPlugin.java:3200`）：`render.current-play-head.enabled`、
`render.current-play-head.drop`、`render.current-play-head`。

### 4. 按钮图标实体

**兜底代码不要动**（`PhysicalTableManager.java:3708`）：按钮离桌 2.1 格、椅子 3.1 格，
相差 1.0 格而清理半径只有 0.95。只扫桌面和椅子的话，**升级前生成的按钮图标会永久留在世界里**
（图标已删，`actionEntities` 不再追踪它们），所以 `purgeResidualWorldArtifacts`
要把按钮位置也加进热点。

## 二、手牌交互：判定框实体

### 5. 牌身上的 Interaction 判定框（两次删除，理由不同）

这一条最容易被「优化」回来，务必读完。

**第一次删除**：手牌判定从「牌上挂 Interaction」改成**射线与牌平面解析求交**
（`pickHandCard`）。原因（`PhysicalTableManager.java:3104`、`:6084`）：

> Interaction 的碰撞箱是**正方形**，在牌面之外的深度方向鼓出约半个牌宽。
> 那圈里右键会触发事件但求交判不中，只能吞掉，于是**贴着牌边点桌面既选不到牌也放不了方块**。

**连带删掉的键**：

```
render.card-hitbox.length / .width / .height
render.card-hitbox
render.card-hitbox-offset.lateral / .depth / .vertical
render.card-hitbox-offset
```

**第二次又加回来了一个，但语义完全不同**：现在牌上确实挂着 `Interaction`
（`spawnHandCardCapturer`），因为**空手右键空气时 `PlayerInteractEvent` 根本不触发**
——Paper 的 `handleUseItem` 开头 `ItemStack.isEmpty()` 为真就直接 return，
`callPlayerInteractEvent(..., RIGHT_CLICK_AIR, ...)` 在被跳过的那一段里。
表现是「牌会发光但点不动」（发光走每 tick 服务端射线，与点击包无关）。

关键区别：**它只负责把事件引进来，不负责精度**。命中哪张牌仍然完全交给 `pickHandCard`。
尺寸被严格收紧到与拾取几何一致，所以不会重建那个死区：

- 宽 = 拾取通道宽（`handCardCapturerWidth`，严格等于 `hand-spacing`）
- 高 = 两态拾取盒的并集（`handCardCapturerEnvelope`）

**不要给捕获器加边距、倍率或最小尺寸。** `HandCardCapturerGeometryTest` 有一条断言专门拦这个，
注释原文：「任何『顺手放宽一点让它好点』的改动都会在这里变红——那类改动恰好就是死区的成因。」

### 6. 悬停向后偏移（card-hover.backward-offset）

**删的是**：悬停时让牌沿法向（牌面朝向）平移一点。

**连带删掉的键**：`render.card-hover.backward-offset`。

**理由**（`DoudizhuPlugin.java:4586`、`RETIRED_RENDER_KEYS:3183`）：沿法向平移会让**牌面所在的平面**移动，
射线与牌平面的交点跟着悬停前后漂移，形成闭环：

```
命中 → 放大/位移 → 交点漂移 → 脱靶 → 缩回 → 又命中 → …
```

悬停反馈现在只保留 `render.card-hover.scale`（**只放大长宽，厚度恒定**）与 `.lift`。
长宽方向的放大不移动牌面所在平面，所以判定包络在横向竖向取最大值即可严格覆盖。

**推论**：任何新的悬停反馈都不许沿法向移动牌。

### 7. 已选中牌的额外放大

**删的是**：牌被选中后再放大一档。

**配置键刻意保留**（`config.yml:112`）：

```yaml
selected-card:
  # 已选中的牌当前不再额外放大，保留此项仅兼容旧配置
  scale: 0  # 默认 1.00
```

这是**唯一一个「功能删了但键留着」**的例子，因为删键会让旧配置报错。不要把它加进
`RETIRED_RENDER_KEYS`，也不要真去实现它。

## 三、其他判定框配置

### 8. 椅子与按钮判定框尺寸手调项

**删的是**：手调判定框宽高。现在按按钮文字缩放**自动推算**。

**连带删掉的键**（`RETIRED_RENDER_KEYS:3163`）：

```
render.chair-hitbox.width / .height / render.chair-hitbox
render.button-hitbox.width / .height
render.button-scale
render.button-roll-degrees
render.button-hover
```

理由：「留在配置里只会让人以为还能调」（`migrateChairHitboxConfig` 注释）。

### 9. 椅子朝向旋转

**连带删掉的键**：`render.chair-visual-offset.rotation-degrees`。

**理由**（`:3186`）：这个键**没有任何读取点**，椅子朝向由座位方位算。改它不会有反应。

## 四、绝不能删的键（反向清单）

`PRESERVED_RENDER_KEYS`（`DoudizhuPlugin.java:3211`）——**用户明确要求保留**，
迁移时绝不能顺手删：

```
render.button-offset.distance
render.button-offset.height
render.button-hitbox-offset.lateral
render.button-hitbox-offset.depth
render.button-hitbox-offset.vertical
```

注意 `button-hitbox.width/height`（尺寸）已退休，但 `button-hitbox-offset.*`（位置微调）**要留**。
两组名字很像，别看错。

## 五、玩法与方法

### 10. 德州扑克玩法

**删的是**：整个德州玩法。

**兜底代码不要动**（`DoudizhuPlugin.java:3613`）：启动恢复牌桌时，`gameType` 不是
`DOUDIZHU` 的旧记录直接 `deleteTable` 清掉，否则每次启动都会尝试恢复一个不存在的玩法。

### 11. GameTable.openHandsForAll() / refreshHands()

**删的是**这两个方法（`GameTable.java:1371`）。它们做的事就是逐个座位直接调下层刷新，
调用点改成直接调下层即可。

### 12. 「数值精确等于旧默认值就强制覆盖」式迁移

**全部删除**（`DoudizhuPlugin.java:3311`）。这类迁移会把玩家**刻意调成恰好等于旧默认值**的配置
悄悄改掉。不要再写这种迁移。

## 六、死代码（声明了但从未生效）

以下不是「删掉的功能」，而是**当前就是死的**，容易被误认为现成机制而直接拿来用：

| 符号 | 位置 | 状态 |
|---|---|---|
| `CARD_HOVER_GRACE_TICKS` | `PhysicalTableManager.java:61` | 常量无任何引用 |
| `hoverGraceTicksByViewer` | `:191` | 只有 `clear` / `remove`，**没有任何 `put`/`get`**，从未参与判断 |
| `CARD_HOVER_SWITCH_TICKS` | `:62` | 同上 |
| `hoverCandidateTicksByViewer` | `:190` | 同上 |

含义：**悬停迟滞（hysteresis）目前并不存在**。若要做「未选中用小判定区、悬停后放大」
这类迟滞，是从零实现，不是启用现成开关。而且那会让判定几何变成有状态的，
与 `selectedEnvelopeIsAnimationInvariant` 锁的「判定是动画的不动点」设计前提冲突，
属于改架构，需先取得 linmumua 同意。

## 七、维护约定

1. 再删功能时，同步在本文加一节：删了什么、为什么、连带删哪些键、还有什么兜底代码在为它服务。
2. 往 `RETIRED_RENDER_KEYS` 加键时**子键先删、父节点最后删**，避免遗留空 section。
3. 兜底用的「考古常量」（如 `RETIRED_STATUS_AVATAR_VERTICAL_OFFSET`）不要当可调参数，
   也不要因为「功能都删了」而清掉——老世界里的残留实体还靠它回收。
4. 本文与代码注释是互补关系，**不要为了写本文而删代码注释**。
